# 前后端系统功能设计 (Cloud Platform)

为了支撑起“大小模型协同的视频分析”这一核心业务，云端中心管控平台（前端 React + 后端 Java）需要扮演**指挥中心、大屏展示、模型中枢、以及大模型调度**的角色。

下面是针对该系统的前后端详细功能规划。

---

## 1. 前端系统功能规划 (React)

前端主要面向管理员、安保人员和算法工程师，功能应侧重于直观的视觉交互与便捷的管理。

### 1.1 综合数据大盘 (Dashboard)
*   **全局概览**：展示当日告警总数、在线边缘设备数量、处理率等核心指标。
*   **趋势图表**：分时段告警趋势折线图、不同类型事件（如人员入侵、异常聚集）的饼图。
*   **大模型洞察精选**：展示近期由多模态大模型判定为“高危”的核心预警。

### 1.2 实时视频监控 (Live Surveillance)
*   **多画面分屏监控**：支持 1x1, 2x2, 3x3 视频墙，拉取来自边缘设备（经由 SRS/MediaMTX）的实时流（WebRTC/FLV）。
*   **AI 叠层开关**：支持在画面上切换显示/隐藏小模型的检测框（Bounding Box）。
*   **云台控制 (PTZ)**：若边缘摄像头支持，提供基础的方向转动和焦距调整。

### 1.3 告警中心与人工复核 (Alert Center)
*   **告警列表**：时间倒序展示各类告警，包含时间、地点、截图（Snapshot）或短视频。
*   **大模型深度报告页**：当该事件触发了大模型分析时，展示大模型生成的自然语言安全报告、场景研判和危险等级。
*   **数据闭环标注（人工复核）**：提供“误报 (False Positive)”、“漏报”按钮。操作后，该告警图片会自动被打标签并送入后台待训练数据集。

### 1.4 设备与任务管控 (Device & Task Management)
*   **设备台账**：边缘设备（Video Sentinel）的注册、状态监控（CPU、温度、NPU 内存占用、网络延迟）。
*   **可视化规则配置 (重点)**：
    *   在视频画面的静帧上，通过鼠标拖拽绘制 ROI（感兴趣区域）多边形、越线检测线。
    *   配置该设备的告警策略：如“仅夜间 22:00-06:00”，“当 ROI 区域内出现 >3 个人时报警”。
    *   一键下发配置到边缘终端。

### 1.5 模型训练与下发 (Model Center)
*   **小模型版本库**：展示已训练好的 YOLO 模型列表及版本。
*   **数据集管理**：管理从“误报”中收集上来的图片集。
*   **触发训练**：提供触发后台重训模型的入口。
*   **OTA 部署**：选择指定模型，选中一批边缘设备，一键执行模型远程推送与无缝热重载更新。

## 2. 后端系统功能规划 (Java / Spring Boot)

后端是整个系统的心脏，负责数据流转、设备连接维持和第三方 AI 的调度。

### 2.1 边缘设备网关 (Edge Device Gateway)
*   **信令通道**：集成 MQTT Broker (或 WebSocket 服务)，用于与边缘的 C++ 程序建立长连接，实时接收心跳和告警。
*   **指令下发**：将前端生成的 JSON 配置（ROI 规则、工作时间、流媒体推送指令）可靠地下发到设备，并保证设备收到（QoS 机制）。

### 2.2 流媒体调度管理 (Streaming Manager)
*   **推拉流映射**：与后端的 SRS 或 MediaMTX 流媒体服务器联动。当下发指令让边缘端开始推流后，后端生成对应的 WebRTC 拉流 URL 给前端播放。
*   **带宽控制**：超过一定时间无人观看的流，自动下发指令让边缘端停止推流，节省云端带宽。

### 2.3 告警处理引擎 (Event Processing Engine)
*   **清洗与去重**：对边缘端上报的告警数据进行时间窗口内的去重。
*   **大模型触发路由器 (Large Model Router)**：核心逻辑所在。并非所有告警都送给大模型。后端需要根据规则（如：告警级别=High，或小模型置信度 < 0.6 但目标在核心禁区）触发调用。

### 2.4 多模态大模型编排层 (Large Model Orchestrator)
*   **Prompt 工程与拼装**：将接收到的边缘端告警图片，连同特定的 Prompt（如：“你是一个安全巡检专家，请分析图片中是否有人员存在安全违规，如未戴安全帽、明火等”）一起提交给第三方大模型 API (如 阿里通义千问-VL, GPT-4o 等)。
*   **结果解析**：接收大模型返回的 JSON/文本，提取危险等级，存入数据库并实时推送（如通过 SSE/WebSocket）给前端告警大屏。

### 2.5 训练流水线与存储对接 (Pipeline & Storage)
*   **对象存储接入**：集成 MinIO 或 阿里云 OSS，存储所有的告警截图、短视频片段和待训练图片。
*   **训练任务调度**：后端提供接口，当触发重训时，向 GPU 服务器发送训练指令（可以通过 Message Queue 或直接调用 Python API），并监控训练进度。
*   **模型文件分发服务**：作为边缘设备的 HTTP 文件服务器，供设备在收到 OTA 升级指令时安全下载 `.om` 格式的模型文件。

### 2.6 基础业务支撑 (Base Services)
*   **RBAC 权限管理**：用户登录、角色管理（管理员、操作员、算法人员）、日志审计。
*   **关系型数据存储**：Mybatis/JPA 对接 MySQL/PostgreSQL 存储业务数据。

## 3. 功能交互时序示例 (从报警到展示)

1. **[Edge C++]** 视频流 -> 画面缩放 -> 小模型(YOLO)推理出“人” -> 判断命中 ROI 区域。
2. **[Edge C++]** 截取画面 -> 通过 MQTT 发送 JSON 事件（含图片 URL 或 Base64）到云端。
3. **[Java 后端]** 接收 MQTT 事件 -> 判定该区域是高风险区 -> 将图片传给 **大模型 API**。
4. **[大模型 API]** 识别图片，发现图中人员拿有火把，返回 `{"level":"CRITICAL", "desc":"发现人员持明火进入危化品区"}`。
5. **[Java 后端]** 入库并生成高级别告警 -> 通过 WebSocket 推送给前端。
6. **[React 前端]** 告警中心弹出红色警报卡片，安保人员点击查看大模型描述，并可立刻打开该摄像头的 WebRTC 实时视频流进行查看。
